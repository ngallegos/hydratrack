# 01 — Scaffold

## Project layout

| Path | Purpose | .NET analogy |
| --- | --- | --- |
| `pubspec.yaml` | Dependencies, SDK constraint, assets | `.csproj` |
| `pubspec.lock` | Pinned resolved versions (committed for apps) | `packages.lock.json` |
| `lib/` | App source; `lib/main.dart` is the entrypoint | project root + `Program.cs` |
| `test/` | Tests mirror `lib/` | test project |
| `android/`, `web/` | Platform runners generated by `flutter create` | platform heads (MAUI-style) |
| `analysis_options.yaml` | Lint and analyzer rules | `.editorconfig` + analyzers |

## Everything is a widget

`runApp(const HydraTrackApp())` hands a root widget to the framework. Widgets are immutable
descriptions of UI; `build()` returns a tree of them and Flutter diffs it against the previous
tree. A `StatelessWidget` has no mutable state, so `build` depends only on its constructor args
and inherited context (theme, media query).

`const` constructors let Flutter reuse identical widget instances instead of rebuilding them.

## Theming

`ColorScheme.fromSeed` derives a full Material 3 palette from one color. `MaterialApp` takes both
`theme` and `darkTheme` and follows the system setting by default, which is why light/dark support
costs nothing here.

## Analyzer strictness

`strict-casts`, `strict-inference`, and `strict-raw-types` turn implicit `dynamic` into errors, the
closest Dart gets to "nullable enabled + warnings as errors". Dart null safety is already sound and
always on.

## Testing

`testWidgets` + `WidgetTester` build widgets in a headless test environment. `pumpWidget` renders
the tree; `find.text(...)` queries it like a lightweight UI automation selector.
